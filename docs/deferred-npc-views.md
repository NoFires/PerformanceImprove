# Wrath Deferred NPC Views 0.1.0

**当前发行已合并为 [PerformanceImprove 0.2.0](performance-improve.md)，并随合并版安装。** 本文保留最初独立试验版说明；不要与合并版同时安装。独立包仍未部署，合并版也尚未进行游戏内验证。

2026-10-21。试验性 Mod：普通眷泽城内，进入地图时延迟远处 NPC 的完整模型，接近队伍或镜头后恢复。源码 `src/WrathDeferredNpcViews/`，包 `dist/WrathDeferredNpcViews-0.1.0.zip`。**已实现和完成独立检查，尚未安装、启动游戏或测得收益。** 已安装的 WrathLifecycleFix 订阅清理补丁是另一项功能，不包含这个新功能。

## 范围与用户最新修正

默认 AllNonPartyNpcs=true，不再限制四种市民或 IsExtra；保留一个四种市民的窄范围选项。玩家报告普通眷泽城基本无战斗，例外是第四章第一次进城，因此本版**不把整个第四章排除，也不自行记录一个可能与存档不同步的“第一次”计数**。

本机参考蓝图显示普通 `DrezenCapital` 区域 ID 为 `2570015799edf594daf2f076f2f975d8`，剧情 `ReturnToDrezen` 为 `83a099db95e0e6e4485a20b10ce7c28d`。只给前者启用，后者及其他区域均不启用；这两个蓝图的区分已检查。它是否完全对应用户所称的“第四章第一次”，尚需运行现场确认，不能宣称已识别所有剧情变体。第三至第六章的普通眷泽城均可使用，当前有战斗时不再延迟。

“全部 NPC”指扩大候选范围，不表示关闭所有单位对象：逻辑实体、事实、任务状态、原始唯一 ID、生成事件和生成顺序继续由原游戏执行。跨场景单位、玩家阵营/直接受控单位、同伴/宠物、死亡/布娃娃/肢解单位、变形或 Doll 特殊模型，以及已参与过场、具有不能推迟的状态或指令者，继续走完整模型路径。原本已经使用原生 dummy 的单位不接管。新生成路径目前覆盖普通 UnitSpawner，不改写特殊生成器。容量上限4096，超出者保持原加载。

本轮没有加入模型流式卸载、地图建筑分块、纹理后台生成或 GC 清理；恢复过的单位在本次区域会话内不再重新延迟。不能据此承诺所有 NPC 都不消耗资源，或内存必然下降。

## 实现行为

- 新生成：保留原 SpawnUnit 工厂、蓝图初始化和任务注册，仅在符合条件的资源请求前选择原生 OptimizationDummyUnit。构造后把由本补丁临时选择产生的 HasDummyView 标记还原为 false，避免把本补丁的临时选择写入存档。
- 存档恢复：在 UnitEntityData.CreateView 的常规模型资源请求处改选 dummy，不改逻辑实体或保存标记。变形与 Doll 的提前返回路径没有强行改写。
- 原生 UpdateHasDummyView 对本补丁仍在追踪的临时替身暂缓执行，避免立刻把模型补回或改变临时状态的序列化标记；原生替身和其他单位保持原行为。
- 原加载协程和所有原 yield 执行完，再在加载画面内逐帧补齐附近模型。默认队伍半径45米，UMM可调25至100米；同时检查镜头投影范围，预留屏幕四周40%的边界。以所有直接受控且在场单位的位置计算距离。
- 游戏运行中需要补齐时，每次 Update 最多建立一个完整模型；没有任务时每0.1秒扫描。单次 Unity Instantiate 无法中途抢占，所以这不是硬性帧时间保证。远距离传送或快速移镜头仍可能短暂跳出，需要实测。
- 脚本 GetValue/TryGetValue、过场演员标记、指令 Init/Start 提供同步恢复入口。过场开始、对话开始、加入战斗会请求全量恢复，并停止该区域会话后续延迟。这可能减少收益，保留该保护用于首轮验证。
- 关闭、切到只计时模式或点击 Restore all 时恢复待处理模型；恢复失败时保留追踪并记录，不报告成功关闭。模型切换时保留旧 view，失败尝试重新附着旧 view；附着回调和其他 Mod 的副作用无法靠此回退完全撤销。
- 使用弱引用和 ConditionalWeakTable 记录单位，离开区域会话清空元数据。没有强引用字典长期持有所有 NPC，没有定时强制 GC 或资源卸载。

## 安装与对比

使用现有 UMM 0.32.4，将包内 WrathDeferredNpcViews 文件夹安装到游戏 Mods。沿用游戏已有 Harmony/Unity/游戏程序集，包中不附带这些 DLL。安装需要游戏退出；本轮未自动执行安装。

启动后默认启用广范围候选。UMM 中可以选择 Profile only、调整预热距离、切回四种市民范围或恢复全部模型。关闭后再开启不会重新延迟本次已恢复的单位，比较应重新启动游戏、加载同一存档、走相同入口。

严格检查本机 Assembly-CSharp SHA256：`2cb7160b7154d4ffacc77b9c51b1eb26199e1294300f04fdfc073367b2ef8953`。两个模型工厂必须各保留已核对的两次资源请求，以及第一个请求的 hold=false 指令形状。布局或必需 hook 不匹配则撤销本 Mod 的补丁并报告加载失败；这不能代替完整 Mod 兼容性检查。

`Mods/WrathDeferredNpcViews/Logs/<会话>.csv` 每文件上限2MiB，记录 deferred/warmed/pending/failures、容量跳过、CreateView/SpawnUnit 累计调用与时间、ProfileOnly 和保护状态。计时是同步方法的含子调用总时间，不是完整地图异步耗时，CreateView 与 SpawnUnit 也不能直接相加；原生加载报告及外部进程采样仍须同时记录。计数反映本 Mod 的观测范围，不是全地图资源清单。

下一轮验收：当前 Mod 组合、同存档同入口，对比 Profile only 与启用延迟；检查加载画面结束时附近 NPC、走近远处 NPC、快速移镜头、对话、过场、指令、存读档、离开再回城及关闭功能。重点看总加载时间、走动长帧、延迟/恢复数量、异常和私有内存，而不是只看加载条更早结束。之前旧 Mod 组合的48.812秒只能作历史参考。

独立检查使用真实本机 IL、真实 Harmony 和可执行替身方法，以及纯托管队列/协程检查。**没有运行 Unity 原生实例化、真实 NPC 初始化或完整游戏，因此尚不能证明游戏画面、任务和所有 Mod 回调兼容。** 构建和结果见 `scripts/build-deferred-npc-views.ps1`、`analysis/deferred-npc-views-checks.txt`，包哈希和部署状态见 `analysis/deferred-npc-views-verification.json`。
